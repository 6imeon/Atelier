# Atelier — Setup & Portability Guide

How to move this repo to another machine and get it running. Also serves as context for an AI assistant in VS Code on the new machine.

---

## TL;DR

```bash
# On the new machine, after extracting the zip:
cd canvas-ai

# 1. Install deps (node_modules is NOT shipped)
npm install

# 2. Make sure .env exists with your real secrets (see "Secrets" below)
cp .env.example .env   # only if .env is missing — then edit it

# 3. Create the named Docker volume (compose expects it as external)
docker volume create atelier_atelier-data

# 4. Build and start everything
docker compose up -d --build

# 5. Open the app
open http://localhost:8090
```

If this works, you're done. The rest of this doc explains the gotchas.

## Prerequisites on the new machine

| Tool | Version | Why |
|---|---|---|
| **Docker Desktop** | latest | Runs the 3-service stack (crawl4ai, api-server, web-ui via nginx). |
| **Node.js** | **22.12.x** | Pinned in both Dockerfiles; local `npm install` and dev scripts assume v22. |
| **npm** | **11.9.x** | Set as `packageManager` in [package.json](../package.json). |
| **Git** | any recent | Optional but recommended. |
| **VS Code** | latest | Plus the Claude Code extension if you want AI assistance. |

macOS / Linux / WSL2 on Windows all work. Native Windows (no WSL) is untested.

## What to include / exclude when zipping

### EXCLUDE before zipping (huge / regenerable / secret)

- `node_modules/` — regenerated by `npm install` (~600MB+).
- `dist/` and `packages/*/dist/` — regenerated by build.
- `.turbo/` — turbo cache, regenerable.
- `data/` — local SQLite DB if you ever ran outside Docker. The Docker stack uses a named volume, not this folder, so it's usually empty.
- `*.db`, `*.db-journal`, `*.db-wal` — local SQLite artifacts.
- `.DS_Store` files (macOS).
- `scripts/adidas-screenshots/`, `scripts/engine-previews/`, `scripts/premium-components/` — debug output.

A safe one-liner from the repo root:

```bash
zip -r ../atelier.zip . \
  -x "node_modules/*" "*/node_modules/*" \
  -x "dist/*" "*/dist/*" \
  -x ".turbo/*" "*/.turbo/*" \
  -x "data/*" "*.db*" \
  -x ".DS_Store" "*/.DS_Store" \
  -x "scripts/adidas-screenshots/*" "scripts/engine-previews/*" "scripts/premium-components/*"
```

### INCLUDE (don't accidentally exclude these)

- **`.env`** — `.gitignore`d, so won't come from `git archive`. Must be in the zip OR re-created on the new machine.
- `package-lock.json` — required for reproducible `npm install`.
- `docker-compose.yml`, all `Dockerfile`s, `.dockerignore`.
- `vite.config.ts`, `tsconfig.json` files.
- `packages/web-ui/nginx.conf`.
- `.env.example` — template if `.env` is missing.

## Secrets (`.env`)

`.env` is **gitignored** and contains the keys the app needs. Either ship it in the zip (if you trust the destination) or re-create it on the new machine using `.env.example` as the template.

Minimum required for the app to start:

```ini
OPENROUTER_API_KEY=sk-or-v1-...
```

Other keys you may have set:

| Var | Purpose | Required? |
|---|---|---|
| `OPENROUTER_API_KEY` | LLM calls. | **Yes** |
| `ATELIER_API_KEY` + `VITE_ATELIER_API_KEY` | API auth (must be the same value). | If `AUTH_MODE=apikey` or `both` |
| `AZURE_TENANT_ID`, `AZURE_CLIENT_ID` | Backend Entra validation. | If `AUTH_MODE=entra` or `both` |
| `VITE_AZURE_TENANT_ID`, `VITE_AZURE_CLIENT_ID` | SPA Entra login (same values, exposed to the browser bundle). | If `AUTH_MODE=entra` or `both` |
| `MONGO_URI` | Analytics/learning layer. App works without it. | Optional |
| `AUTH_MODE` | `apikey` (default) / `entra` / `both`. | Optional |

> ⚠️ **Critical:** the web-ui bakes `VITE_*` vars into the JS bundle at **build time**. If you change a `VITE_*` value, you MUST `docker compose build --no-cache web-ui` (or at least `docker compose up -d --build web-ui`). Restarting the container alone will not pick up the new value.

## Docker volume — preserving your data

The SQLite database and any uploaded assets live in a Docker volume named `atelier_atelier-data` (declared `external: true` in [docker-compose.yml](../docker-compose.yml#L77-L80)).

**On a new machine the volume does not exist.** You must create it before `docker compose up`, otherwise compose will error out.

```bash
docker volume create atelier_atelier-data
```

Starting empty is fine — the api-server initializes the SQLite schema on first boot.

### To carry your existing data over

On the **old** machine, dump the volume to a tarball:

```bash
docker run --rm \
  -v atelier_atelier-data:/data:ro \
  -v "$PWD":/backup \
  alpine tar czf /backup/atelier-data.tgz -C /data .
```

Ship `atelier-data.tgz` alongside the repo. On the **new** machine:

```bash
docker volume create atelier_atelier-data
docker run --rm \
  -v atelier_atelier-data:/data \
  -v "$PWD":/backup \
  alpine sh -c 'cd /data && tar xzf /backup/atelier-data.tgz'
```

Then `docker compose up -d` as normal.

## Architecture summary (so an AI in VS Code can orient quickly)

- **Monorepo** managed by npm workspaces + turbo. Packages live under [packages/](../packages/).
  - `packages/api-server` — Node.js Express API (port 8080).
  - `packages/web-ui` — Vite + React SPA, served in production by nginx (port 80 inside container, mapped to 8090 on host).
  - `packages/sdk` — shared TypeScript SDK consumed by both web-ui and external scripts.
  - `packages/mcp-server`, `packages/figma-plugin` — not part of the Docker stack.
- **Single source of truth for env**: monorepo-root `.env`. Vite reads it via `envDir: monorepoRoot` in [packages/web-ui/vite.config.ts](../packages/web-ui/vite.config.ts). The api-server reads it via compose's `env_file: [.env]`.
- **Three Docker services** (see [docker-compose.yml](../docker-compose.yml)):
  1. `crawl4ai` — `unclecode/crawl4ai:0.7.4`, used for headless website fetching.
  2. `api-server` — built from [packages/api-server/Dockerfile](../packages/api-server/Dockerfile), depends on crawl4ai healthy.
  3. `web-ui` — built from [packages/web-ui/Dockerfile](../packages/web-ui/Dockerfile), nginx serves static bundle and proxies `/api/*` to api-server. Depends on api-server healthy.
- **Project name** in compose is `atelier`, all containers/images use the `atelier-*` prefix.
- **Build-time vs runtime envs**: web-ui bakes `VITE_*` at build; api-server reads at runtime. This matters for any deployment automation (Ansible templating, CI, etc.) — see [PRODUCTION-READY.md](PRODUCTION-READY.md) and the project memory for Ansible deploy.

## Verification checklist after first start

```bash
# All three containers healthy
docker compose ps

# API health (via nginx proxy)
curl http://localhost:8090/api/health
# → {"status":"ok"}

# API health (direct)
curl http://localhost:8080/api/health
# → {"status":"ok"}

# Web UI loads
open http://localhost:8090
```

If sign-in is configured (`AUTH_MODE=entra` or `both`), also confirm that the bundle picked up your Azure values:

```bash
# Should print the tenant id you set, NOT a blank string
curl -s http://localhost:8090/ | grep -oE 'authority:"[^"]*"' | head -1
```

If it's blank, `VITE_AZURE_TENANT_ID` was not set when the bundle was built — fix `.env` and rebuild with `docker compose up -d --build web-ui`.

### If you change the host or port

The Entra app registration in Azure must include the new origin as a redirect URI. The app uses `redirectUri: window.location.origin` (no path), so e.g. `http://localhost:8090` and `https://atelier.example.com` are separate redirect URIs that both need to be registered.

## Common gotchas

- **`docker compose up` fails with "external volume not found"** → run `docker volume create atelier_atelier-data` first.
- **Web UI loads but sign-in does nothing** → `VITE_*` vars weren't baked. Confirm `.env` has them, then `docker compose build --no-cache web-ui`.
- **Port 8090, 8080, or 11235 already in use** → set `WEB_PORT`, `API_PORT`, or `CRAWL4AI_PORT` in `.env` (compose reads them, see [docker-compose.yml](../docker-compose.yml)).
- **Node version errors during local `npm install`** → make sure you're on Node 22.12.x. Use `nvm use 22` if you have nvm.
- **`.env` accidentally committed** → it's in `.gitignore`; if it shows up as untracked it's normal, if as modified you've got a stale entry to clean up.

## Local dev (without Docker)

If you want to iterate on the web-ui with HMR instead of rebuilding the nginx image each time:

```bash
# Terminal 1 — keep crawl4ai + api-server running in Docker
docker compose up -d crawl4ai api-server

# Terminal 2 — Vite dev server with HMR
cd packages/web-ui && npm run dev
# → http://localhost:5173 (proxies /api to localhost:8080)
```

The api-server inside Docker still serves on `localhost:8080`, and Vite's dev server proxies `/api/*` to it (configured in [packages/web-ui/vite.config.ts](../packages/web-ui/vite.config.ts)).
